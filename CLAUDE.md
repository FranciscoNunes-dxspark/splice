# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Splice is a keyboard-driven git client for the terminal, built with Ink (React for the terminal) on Node 22+. Plain JavaScript ES modules with `.jsx` for components; no TypeScript, no linter config. It shares some files with its sibling Trawl (a SQL Server client): `scripts/shared-check.js <sibling checkout>` reports how the shared files (its `SHARED` list: `text.js`, `ui/parts.jsx`, `ui/hooks.js`, `mouse.js`, `selection.js`, `clipboard.js`, `jsx-hooks.js`, `register.js`, `version.js`, `help-layout.js`, `ui/HelpView.jsx`, `keymap.js`, `usercommands.js`, `palette.js`, `ui/Palette.jsx`, `run.js`, `credentials.js`, `claude-cli.js`, `family.js`, `scripts/build.js` and itself; `run.js`, `credentials.js` and `claude-cli.js` are in the apps that use them, so one missing here isn't drift) differ from Trawl's, ignoring the apps' names, and exits with 1 on drift; `--diff` shows the lines. Keep them the same: a change to one goes into the other app too, and anything only one app needs lives in its own file (Splice's `ui/diffstyle.js` and `ui/prList.js`).

## Commands

```bash
npm test                                                       # whole suite (node:test)
node --import ./src/register.js --test test/parse.test.js      # one file
node --import ./src/register.js --test --test-name-pattern="rebase" test/*.test.js   # tests matching a name
npm start                                                      # run from the checkout (needs a real TTY)
node bin/splice.js C:\some\repo                                # open a specific repo
npm run build                                                  # Bun-compiled executable for this machine → dist/
npm run build:all                                              # every release target
node scripts/logo.js                                           # regenerate assets/ from src/pet.js
node scripts/shared-check.js ../trawl [--diff]                 # drift in the files shared with Trawl
```

`bin/splice.js` sets `NODE_ENV=production` only while it imports React and Ink, which picks React's production build (several times faster to render), then removes it so git hooks don't inherit it. The compiled builds define it in the bundle instead. Tests run React's development build.

`patches/ink+6.8.0.patch` (applied by `patch-package` on `npm install`, so CI and the release builds get it too) keeps Ink's width and tokenize caches from one frame to the next rather than starting each frame empty; the same patch as Trawl's, where it took about 30% off a keystroke. Upgrading Ink means checking `build/output.js` still has `OutputCaches` and remaking the patch (`npx patch-package ink`), or dropping it once Ink does this itself.

`--import ./src/register.js` is required whenever Node loads `.jsx`: it installs a module hook (`src/jsx-hooks.js`) that compiles `.jsx` with esbuild on import. There is no dev build step. CI runs `npm test` on Linux and Windows, so path handling and line endings must work on both (`.gitattributes` forces LF).

Releases are automatic: every push to main (except Markdown-only ones) runs the Release workflow, which publishes the latest release's version with the patch raised, or `package.json`'s version when that's higher (bump it there for minor or major). It sets the version in the runner before building and commits nothing back, so `package.json` on main lags behind the releases. Compiled builds get the version via `process.env.SPLICE_VERSION` (defined by `scripts/build.js`), which also sets `COMPILED`; from a checkout `src/version.js` reads `package.json`, and the update check is skipped.

## Architecture

The layering, bottom to top:

- **`src/git.js`**: the only way git is spawned. Forces `GIT_TERMINAL_PROMPT=0`, `GIT_OPTIONAL_LOCKS=0`, `GIT_EDITOR=true`, `core.quotepath=false`, `color.ui=false`. Git runs with no terminal, so nothing may ever wait on a prompt or an editor: off Windows it starts detached (a session without a controlling terminal, so ssh, ssh-keygen or a pinentry fail at once rather than ask), and `GPG_TTY` is dropped. Failures throw `GitError` carrying git's own stderr (a signing failure gets `signing.js`'s explanation first); aborts set `cancelled`. Commits Splice makes by hand (`commit-tree`, as for a stash of some lines) pass `--no-gpg-sign`.
- **`src/parse.js`**: pure parsers for porcelain/log/ref output plus the format strings they expect (`LOG_FORMAT`, `REF_FORMAT`, ...). Keep parsing here and pure; most unit tests target it. Same for `src/patch.js` (diff parsing and building partial-staging patches for `git apply --cached`), `src/conflict.js` (conflict markers: parsing, taking a side of one block, keeping each line's ending), `src/search.js` (the viewer's search, and `wordChanges` for word-level diff highlights; `markRanges` restyles parts of a line's segments for both), `src/review.js` (placing PR review threads under their diff lines), `src/graph.js` (the commit graph, laid out as git-graph does: each commit traced to one branch, a column per branch with the default branch left-most; the log is read without `--graph`; between the commits come connector rows, which have only a `graph`), `src/message.js` (the commit message file `M` writes for your editor, and what git keeps of it), `src/split.js` (a diff's lines paired into two columns for `w`, side by side) and the pure parts of `src/rebase.js`, `src/hosting.js`, `src/undo.js`, `src/cleanup.js` and `src/history.js`. The default branch comes from `defaultBranch(refs, remotes)` in `parse.js` (the remote's HEAD, from the ref listing already loaded); use it rather than asking git or the PR host again.
- **`src/repo.js`**: reads everything a view needs into one `data` object (status, changes, graph, refs, stash, worktrees, remotes, in-progress `state`, a `signature` for change detection). Starting git costs about 100 ms on Windows, so loads keep the number of git processes low: one ref listing serves both the views and the signature (it lists every ref, and keeps the views' ones), the graph's `git log --all` is read again only when a ref, HEAD, the shallow boundary or the limit changed (otherwise the laid-out graph is reused), and the stash list and remotes are reused until their file in the common dir changes. `loadRepo().signature` must equal `snapshot().signature` byte for byte when nothing changed, or every poll reloads; `test/repo.test.js` checks this.
- **`src/actions.js`**: every user-facing git operation, written once. Both key handlers and slash commands call these with `ctx`. Confirmation prompts for destructive operations live here (`ctx.confirm({..., danger: true})`).
- **`src/commands.js`**: the slash-command table (`name`, `args`, `desc`, optional `complete: 'refs' | 'repos'`, `run(ctx, rest)`) and completion. Args in `[brackets]` are optional, so selecting the command runs it immediately.
- **`src/ui/App.jsx`**: owns layout, focus, the prompt, overlays, the activity log, the 3-second poll that reloads when `snapshot().signature` changes, and builds **`ctx`**: a stable object (kept in a ref) exposing `data` (getter), `exec`, `git`, `note`, `confirm`, `prefill`, `reload`, `host()`, `show*` overlays, etc. Read the `Object.assign(ctx, {...})` block in `App.jsx` before adding an action. `ctx.exec` runs a visible, cancellable git command and reloads afterwards; `ctx.git` is a silent read. For "pick one from a list" use `ctx.showPicker({ title, hint, items | load, onPick, keys })` (`src/ui/Picker.jsx`); an overlay opened from a picker returns to it when closed.
- **`src/ui/*View.jsx`**: one component per tab. Views must check `ctx.viewHasKeys()` (or `ctx.overlayHasKeys()` in overlays) at the start of their `useInput` handlers so keys don't fire while the prompt, an overlay or a confirm has focus. `useListNav` in `src/ui/hooks.js` is the shared cursor/scroll logic.

Cross-cutting pieces:

- **Pull requests** (`src/hosting.js`): `hostFor(data, config)` picks GitHub (via `gh`), Azure DevOps (via `az` + `azure-devops` extension) or GitLab (via `glab api`, for gitlab.com, hosts named gitlab, or ones the config's `hosts` maps to it) from the remote URL. Splice never handles tokens; it shells out to those CLIs. Server JSON is normalised into one PR shape (`githubPr`, `azurePr`, `gitlabPr`), and review comments into one thread shape (`githubThreads`, `azureThreads`, `gitlabThreads`), which `TextViewer` draws into a PR's diff (`/reply` answers one). Azure and GitLab PR diffs are computed locally after fetching both branches (GitLab's from `refs/merge-requests/<iid>/head`). The PR list is fetched once for the PRs and Branches views (`usePrList` in `src/ui/prList.js`). `App` takes a `makeHost` prop (default `hostFor`) so tests can stub the host.
- **Conflict forecasts** (`src/forecast.js`, `src/ui/forecasts.js`): `git merge-tree --write-tree` (git 2.38+, checked once with `gitVersion`) says whether two commits would conflict without touching the working tree; answers are cached per pair of hashes. The Branches view works them out in the background, one git at a time, for the selected branch and the local ones on screen (`useForecasts`); `merge`/`rebase` questions and `/forecast` use the same cache. `run`'s `codes` option is how merge-tree's exit code 1 ("conflicts") comes back as a result rather than an error.
- **Sync and update-branch** (`src/sync.js`, actions `sync`, `updateBranch`): `/sync` fetches, then fast-forwards branches that are only behind (`update-ref --stdin` with old values for the others, `merge --ff-only` for the current one, both with "sync" in the reflog, which `undo.js` knows); `/update-branch` rebases onto the default branch with `--autostash`, and a stack from its top with `--update-refs` (detaching first, since git skips a branch checked out anywhere). The plans and report text are pure in `sync.js`.
- **Shipping, reviewing and backporting** (`src/prflow.js`, pure; actions `ship`, `reviewPr`, `backport`, `changelog`): built only on the host interface (`pr(id)`, `headRef(pr)`, `mergedSince(date)` besides the others), so each works on all three hosts. `/ship` remembers the branches it shipped (`shipped`) and the merge method per repository (`shipMethods`) in the config; `/review-pr` checks a PR out as `pr-<n>` in `../<repo>-pr-<n>`, which `/cleanup` removes once it's merged; a backport stopped on a conflict keeps its state in `.git/splice-backport.json` for `/continue`.
- **Interactive rebase** (`src/rebase.js`): no editor. Splice writes the todo itself under `.git/splice-rebase/` and passes it through `GIT_SEQUENCE_EDITOR`; reword becomes `pick` + `exec git commit --amend -F <file>`.
- **Undo** (`src/undo.js`, `z` / `/undo`): reflog-based for anything that moves HEAD or the branch. Discards can't be read back from the reflog, so every action that throws work away keeps a copy first (`captureDiscard` / `saveDiscard`, under `.git/splice-undo/`); a new destructive action must do the same.
- **Claude** (`src/claude.js`, actions `describeCommit`, `draftPr`, `claudeLook`, `claudeRef`, `claudeResolve`, `claudeBlame`): runs `claude -p` with the user's sign-in, the input (a diff) on stdin. The flags skip MCP servers, settings files and skills, which cuts a call from ~15 s to ~7 s. Writing messages gets no tools (a message with a body goes into the commit message file, as `M` writes it); explaining (commits, PRs, blame lines), reviewing and resolving conflicts get read-only `Read`, `Grep`, `Glob`. `cli.jsx` passes `ask` to `App` as `askClaude`, exposed as `ctx.askClaude`; tests pass a stub, so they never call the real CLI. Prompts and answer parsing are pure functions in `claude.js`.
- **Updates** (`src/update.js`): once a day, GitHub's public releases API, then `gh api` as a fallback (the repo is private). A newer release is then installed in the background (`installUpdate`: download next to the executable, check `SHA256SUMS.txt`, swap by renaming; on Windows the running exe is renamed aside and `removeOldExecutables` deletes it on a later start). Release file names must match `TARGETS` in `scripts/build.js`. `cli.jsx` passes both to `App` as the `checkUpdate` and `installUpdate` props, only in compiled builds; tests leave them out or pass stubs, so they never go online or replace anything. The last answer is saved in the config through `App`'s `setConfig`. Don't write the config file from anywhere else: `App` saves its whole copy and would overwrite it.
- **Mouse** (`src/mouse.js`, design and open work in `docs/mouse.md`): `terminalMouse` strips SGR mouse reports out of `stdin.read` before Ink sees them and hands them to `App` as the `mouse` prop (`{ subscribe, enable, stdout, claimDrags }`); tests pass a fake. Asking for the mouse stops the terminal selecting text, so Splice does it: Ink draws through `mouse.stdout`, which keeps the last frame; a drag is painted over it in reverse video (again after every frame) and copied on release through `clipboard.js` (`src/selection.js` is the pure part). Clicks reach `App` on release, and only when the button didn't move. On Windows the console only sends the mouse as text in VT input mode: Node 22.17+ sets it with raw mode, the Bun builds set it through `bun:ffi`, older Node gets no mouse. `App` hit-tests the tabs, prompt and suggestions itself and gives the main area's events (`y` relative to it, `double` on a double-click) to the component on screen, which registers with `useMouse(ctx, handler, { top, drags })` from `hooks.js` (`top`: where it starts in the main area, for a component under another; `drags(press)`: where it selects for itself, which `App` passes to `mouse.claimDrags`, so a drag starting there skips the screen selection and arrives move by move as `{ drag, x, y, from }`, the last with `release`). Clicks count up to `triple`. Views name their `useInput` handler `keys` so a double-click can call `keys('', { return: true })`; `useListNav` has `pick(row)` and `scrollBy(n)`. A view's rows start one line under its panel's top border, plus any header lines it draws above them.
- **Notifications** (`src/notify.js`, Trawl's plus `prNews`; not shared): `App`'s `task` calls the `notify` prop (cli.jsx writes a bell and OSC 9 / OSC 777) when a run that wasn't cancelled took over `notifyAfter` seconds (10), and `usePrList` compares each PR list with the one before and hands what changed on your own PRs (checks finished, a new review) to `ctx.prNews`. The `notify` setting turns both off; tests pass a recorder or nothing.
- **Drops** (`src/drop.js`, pure; `openDropped` in `actions.js`): a terminal types a dropped path, so `globalKeys` takes input of more than one character that is nothing but existing absolute paths as a drop: a folder opens (or lists the repositories in it), a file of the open repository shows its history.
- **The family** (`src/family.js`, shared and never edited here; Splice's side in `src/siblings.js`, `src/take.js`, pure): apps never start each other, they copy command lines for each other (`copyFor` in `actions.js` copies and says "Copied for <App>"). `/take <context>` (`take`; a bare `family:v1:…` at the prompt too, in `runLine`) opens blame at an exception's frame or a file's line, or a commit's diff; `/family` lists what the repository offers Bosun, Hail and Trawl (`familyOffers`, never a password); `Y` in the graph and in blame copy `/take commit` and `/take file`; `w` in the graph (`runAt`) makes `../<repo>-at-<hash>` and copies Bosun's `/move`, and `cleanup.js`'s `runAtHash` knows those worktrees. A paste in a view (`pastedLine`, in App's `useKeyTranslation` callback, after the drop check and not while the viewer's search is typed: `ctx.viewerTyping`) opens the prompt with it. Twig's mood goes to `writeMood` and the others' come from `readMoods` every `moodEvery` ms, only with the `familyHome` prop (cli.jsx passes `familyDir()`; tests a temp folder or nothing).
- **Blame of the future and risk before push** (`src/future.js`, `src/risk.js`, pure; actions `future`, `risk`, and `riskBeforePush` in `push`): `F` in blame fetches every open PR's head into `refs/splice/future/*` in one fetch (deleted again after), lists each PR's files once per head (cached), and compares `-U0` hunks in the merge base; the risk score is three gits (the outgoing log with `--raw --numstat`, `cat-file --batch-check`, and 90 days of the touched files).
- **Clipboard** (`src/clipboard.js`): through the OS's own tools (PowerShell's `Set-Clipboard`, `pbcopy`, `wl-copy`/`xclip`/`xsel`), falling back to OSC 52 over SSH or when they fail. `cli.jsx` passes it to `App` as the `copy` prop (`y`); tests pass a recorder.
- **Config** (`src/config.js`): `~/.splice/config.json`, overridable with `SPLICE_HOME` (tests use this). Compare paths with `samePath` (case-insensitive on Windows). Read it as `ctx.config` and change it only with `ctx.setConfig` (App's copy, saved whole). `/settings` (`,`) lists the user-facing settings: the rows are pure in `src/settings.js`, shown and changed by `settings` in `actions.js`; a new setting is a row there plus the README's Settings section.
- **Your own commands and keys, and the palette** (shared with Trawl: `src/usercommands.js`, `src/keymap.js`, `src/palette.js`, `src/ui/Palette.jsx`, all pure but the last): `userCommands(config.commands, builtins)` and `parseKeymap(config.keys, views)` are worked out in `App` (`custom`, kept while those two don't change), and what they leave out is said once at start-up. Your commands are command objects with `user: true` whose `run` is `ctx.runUserCommand`: `expandLines` fills in `$1`/`$*`, and each line goes through `runLine` (what `submit` runs), which resolves false when the line threw, logged an error (`errorCount`, counted in `addEntry`/`updateEntry`) or had a question answered no (`declines`, in `onConfirm`), so a list stops there. `findCommand(name, user)` and `suggestionsFor`'s `user` take them, and the `?` window's sections are `custom.sections`. Keys are rewritten where they come in, not in each view: `useKeyTranslation` (`hooks.js`) wraps Ink's input emitter, so a mapped key reaches every `useInput` handler (views and App's dispatcher alike, and the `keySeq` count) as the key it stands for, or is swallowed and its command line run; it applies only while focus is `'view'` with no overlay or confirm, and it is also where `ctrl+p` opens the palette (from a view or the prompt; before, the views took ctrl+p as `p`). A key picked in the palette is sent the same way (`sendKey`, untranslated) from an effect once the view is back on screen; a command that takes arguments is prefilled instead.
- **Theme** (`src/theme.js`): a dark and a light palette (`DARK`, `LIGHT`); `applyTheme(config)` copies one into `theme` (the Theme setting, `auto` reading `COLORFGBG`) and the accent over it (`setAccent`: yours, or the theme's default, `DEFAULT_ACCENT` or `LIGHT_ACCENT`), at start-up in `cli.jsx` and from `/settings`. Every colour comes from `theme` and is read while drawing: a module-level table of colours uses getters (`TONE` in `PrView.jsx`), never values copied at import, which would keep the palette Splice started with. Use `BULLET` instead of `⏺` directly (Windows renders it as a wide emoji). Use `src/text.js` (`fit`, `wrap`, `stringWidth`) for width-aware truncation, never `.length`.
- **Twig** (`src/pet.js`, `src/ui/Pet.jsx`): the beaver mascot's pixel art and mood-from-repo-state logic, drawn to the same rules as Trawl's Glim (coloured from the accent family plus one warm highlight), with the Git logo as a badge in the corner; `PET` holds the name and species, and the files are named for the role, not the animal, so a new pet is one file plus `node scripts/logo.js`. `assets/` is generated from it by `scripts/logo.js`; don't hand-edit those files.

## Tests

`test/app.test.js` is end-to-end: it builds a throwaway repo in a temp dir, renders `<App>` with `ink-testing-library`, types keys into stdin and asserts on both `lastFrame()` and the real git state. Use its `until(check, what)` helper to wait for frames rather than fixed sleeps. Each feature with UI has its own end-to-end file built the same way (`undo`, `history`, `fixup`, `branches`, `conflicts`, `stash`, `cleanup`); copy the helpers rather than importing them. Other test files are plain unit tests of the pure modules. Tests that make repositories import `test/temp.js` before anything from `src/`: it turns off git's background gc and maintenance (through the environment), which otherwise keep temp folders busy on Windows, and its `removeTemp` is the teardown. Give a test's own polling `git status` `GIT_OPTIONAL_LOCKS=0` so it never takes `index.lock` from under Splice, and let an `until` check that runs git treat an error as "not yet": a ref being replaced mid-rebase can briefly read as broken on Windows.

## Keeping things in sync

Adding or changing a key or command touches several places: the handler (view or `App.jsx`), `src/commands.js` for slash commands, the `?` window's sections in `src/help.js` (data: `[keys, what they do]` rows, drawn by the shared `src/help-layout.js` and `src/ui/HelpView.jsx`; the slash commands section comes from `commands.js` by itself), and the tables in `README.md`. README prose describes behaviour in plain, user-facing language. Commit messages are short sentences describing the change, without type prefixes.
